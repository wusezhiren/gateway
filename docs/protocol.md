# 网关 ⇄ 节点 ESP-NOW 协议

定义见 `components/meshproto/include/meshproto.h`。所有结构体 `packed`、小端。

## 通用帧头

| 字段 | 类型 | 说明 |
|---|---|---|
| magic | u8 | 固定 `0xE5` |
| version | u8 | 协议版本 `MP_VERSION`，不一致的帧直接丢弃 |
| type | u8 | 消息类型 |
| reserved | u8 | 0 |
| seq | u16 | 发送方递增序号，0 保留 |

接收方用 `mp_parse()` 校验 magic、version、type 和最小长度。

## 消息

| type | 名称 | 方向 | 传输 | 内容 |
|---|---|---|---|---|
| 1 | JOIN_REQ | 节点 → 广播 | 明文 | 固件版本、工程名、芯片型号、节点名、通道描述 |
| 2 | JOIN_RSP | 网关 → 广播 | 明文 | target（节点 MAC）、status、网关信道、心跳周期；seq 回填 JOIN_REQ.seq |
| 3 | HEARTBEAT | 节点 → 网关 | 加密单播 | 运行时间、全部通道值 |
| 4 | HB_ACK | 网关 → 节点 | 加密单播 | seq 回填 HEARTBEAT.seq |
| 5 | SET | 网关 → 节点 | 加密单播 | 通道号、值 |
| 6 | STATE | 节点 → 网关 | 加密单播 | 同 HEARTBEAT；ack_seq = 被应答 SET 的 seq |
| 7 | LEAVE | 网关 → 节点 | 加密单播 | 解除配对 |
| 8 | OTA_BEGIN | 网关 → 节点 | 加密单播 | 固件大小、SHA-256、版本、flags（bit0 = force） |
| 9 | OTA_DATA | 网关 → 节点 | 加密单播 | offset、len（≤200）、flags（bit0 = 要求 ACK）、数据 |
| 10 | OTA_ACK | 节点 → 网关 | 加密单播 | 已连续写入的字节数、状态码；seq 回填被应答帧的 seq |
| 11 | OTA_END | 网关 → 节点 | 加密单播 | 发完，节点校验后切换启动分区并重启 |
| 12 | OTA_ABORT | 网关 → 节点 | 加密单播 | 取消升级 |

JOIN_RSP 走广播是因为此时节点还没把网关加为加密 peer，单播加密帧无法解密。

### 通道描述 `mp_ch_desc_t`

| 字段 | 说明 |
|---|---|
| type | 1 = RELAY（0/1），2 = PWM（0..max，千分比） |
| flags | 预留 |
| max | 取值上限 |

每个节点最多 `MP_MAX_CH = 8` 个通道，通道号即数组下标。

## 流程

### 配对与入网

```
节点                                     网关
 │  JOIN_REQ（广播，逐信道扫描）           │
 │ ─────────────────────────────────────> │ 已知节点，或配对窗口打开中 → 接受
 │                                        │ 加节点为加密 peer，节点表落盘
 │  JOIN_RSP（广播，target=节点 MAC）       │
 │ <───────────────────────────────────── │
 │ 绑定网关 MAC + 信道（NVS），加加密 peer  │
 │  HEARTBEAT                             │
 │ ─────────────────────────────────────> │ 与期望值比对，不符则补发 SET
 │  HB_ACK                                │
 │ <───────────────────────────────────── │
```

- 节点先在上次的信道发 JOIN_REQ，每个信道等 150ms，扫完 1~13 后休息 1s 重来。
- 已绑定的节点只接受自己网关的 JOIN_RSP，避免被其他处于配对模式的网关抢走。
- 网关不在配对窗口时，忽略未知节点的 JOIN_REQ。

### 心跳与掉线

- 节点每 `hb_interval_ms`（默认 5s）发 HEARTBEAT，网关回 HB_ACK。
- 节点连续 3 次没收到 HB_ACK → 认为网关丢失，回到扫描（保留绑定）。
  网关换信道（路由器换信道）后节点就是这样找回网关的。
- 网关 `3 × 5s + 1s` 没收到节点消息 → 标记离线。

### 控制

- 网关发 SET，节点执行后回 STATE（ack_seq = SET.seq），网关收到后结束重传。
- 300ms 未应答重发，最多 3 次；同一通道的新命令覆盖未完成的旧命令。
- 节点通道值变动 2s 后存入 NVS，上电即恢复。
- 网关为每个通道维护期望值：没有命令在途时以节点上报为准；节点重新入网后若实际值与期望值不符则补发。

### 解除配对

- 网关发 LEAVE 后删除 peer 和节点表项；节点收到后清除绑定，回到扫描。
- 节点离线时 LEAVE 收不到：节点会一直扫描旧网关，需在节点上长按复位键（C3 为 GPIO9，S3 为 GPIO0）3 秒清除绑定。

### 节点升级

固件由网关暂存在 `node_fw` 分区（见 [cloud.md](cloud.md) 的 `node_ota` 和 [api.md](api.md)），再分片推给节点：

```
网关                                         节点
 │ OTA_BEGIN（大小、SHA-256、版本）            │ esp_ota_begin(空闲分区，顺序写入边写边擦)
 │ ─────────────────────────────────────────> │
 │ OTA_ACK(offset=0, status)                  │
 │ <───────────────────────────────────────── │
 │ OTA_DATA × 8（最后一片要求 ACK）            │ 只接受 offset 紧接着的那片，其余丢弃
 │ ─────────────────────────────────────────> │
 │ OTA_ACK(已连续写入的字节数)                 │
 │ <───────────────────────────────────────── │ ……从 ACK 的 offset 继续下一批
 │ OTA_END                                    │ 核对 SHA-256，esp_ota_end 校验镜像和签名，
 │ ─────────────────────────────────────────> │ 工程名一致、版本更新 → 切换启动分区
 │ OTA_ACK(status)                            │ 0.5 秒后重启
 │ <───────────────────────────────────────── │
 │                         JOIN_REQ（新版本）  │ 首个 HB_ACK 后确认新固件有效
 │ <───────────────────────────────────────── │
```

- 每批 8 片（1600 字节），500ms 没收到 ACK 就从已确认的 offset 重发，连续 20 批没进展放弃并发 OTA_ABORT。
  实测 Korvo 节点 856KB 约 25~30 秒。
- BEGIN / END 超时各重发 5 次（END 等 5 秒，节点要校验签名）。END 的 ACK 丢了不要紧，以节点是否带新版本回来为准。
- 升级期间心跳、SET 照常处理，开关可以正常控制。
- 节点 30 秒收不到升级帧、或链路丢失回到扫描，就放弃本次升级。
- 状态码：0 成功，1 超出分区，2 无法开始（如当前固件还没确认），3 写 flash 失败，4 没有进行中的升级，
  5 数据不全，6 SHA-256 不符，7 镜像或签名校验失败，8 工程名不符，9 版本不比当前新。

防变砖：

1. 节点只写空闲 OTA 分区，bootloader、分区表、正在运行的分区都不碰；传输中断、断电、节点复位只会让这次升级作废
2. 网关推送前核对镜像头：芯片型号、工程名与节点一致、版本更新；从网上下载的再核对 SHA-256
3. 节点切换启动分区前再核对 SHA-256、签名、工程名、版本
4. 新固件首次启动后 60 秒内必须连上网关（收到 HB_ACK）才确认有效，否则自动回滚；确认前崩溃 bootloader 也会回滚。
   网关等节点重新入网：带新版本回来算成功，带旧版本回来报 `rolled_back`
5. 工程名区分固件种类：不同硬件配置的板子用不同工程名（如 Korvo 板 `esp_s3_korvo`），不会互相刷错

## 加密

- `CONFIG_MP_ENCRYPT`（默认开）：配对后双方互加加密 peer，使用 `CONFIG_MP_PMK` / `CONFIG_MP_LMK`（各 16 字符）。
- 网关和所有节点必须使用相同的密钥配置；部署前请修改默认值。
- 广播帧（JOIN_REQ / JOIN_RSP）始终明文。
- 加密 peer 与 SoftAP 客户端共用 17 个硬件密钥。网关 `ESPNOW_MAX_ENCRYPT_NUM=14`（节点上限 14），
  剩下 3 个给配网热点；否则热点最大连接数会被压成 0，手机连不上。

## 兼容性

- 修改任何结构体都要升级 `MP_VERSION`；版本不一致的设备互相不可见。
- 升级消息（OTA_BEGIN / DATA / ACK / END / ABORT，节点 0.3.0 起）已经发布，必须保持兼容，它是已部署节点唯一的升级通道。
  新增消息类型不需要升级 `MP_VERSION`：老固件的 `mp_parse()` 不认识的类型直接丢弃。
- 0.3.0 以前的节点固件不认识升级消息（网关报 `node_no_response`），要先用 USB 烧一次。
